# 边境 · 探索生存 0.3.2

一个运行在 SillyTavern / TauriTavern 前端的探索生存扩展。区域地图、建筑内部、容器、物品、建设和存档都由插件管理。正式游戏直接调用独立的 Chat Completions API，不使用酒馆正文生成，也不解析 Markdown 地图或表情图标。

## 开始使用

### 从 GitHub 安装（推荐）

打开酒馆的 **扩展 → 安装扩展**，粘贴以下仓库地址；若有分支选项，填写 `main`：

```text
https://github.com/agentgeleven-lab/sillytavern-frontier-survival
```

安装后刷新酒馆，点击左下角 **边境 · 探索**。这是 `0.3.2` 预览版；真实宿主与外部模型的验证范围见文末。更新时使用酒馆的扩展更新功能。

### 手动安装与首次游玩

1. 将整个 `frontier-survival` 文件夹放入酒馆的用户扩展目录 `data/<用户>/extensions/`。`manifest.json` 必须直接位于该文件夹内，不要再多嵌套一层。也可放入宿主支持的全局 `extensions/third-party/` 目录。
2. 刷新酒馆。点击左下角 **边境 · 探索**，或在扩展设置中点击打开按钮。
3. 点击 **先体验离线演示**，先试地图、开门、搜索、拿取与建设。
4. 正式游玩：在 **游戏设置** 填写独立 API 地址、模型 ID、可选密钥并保存。地址支持 `https://example.com/v1` 或完整 `/chat/completions` 地址。
5. 新游戏界面可以读取当前角色卡与其主绑定世界书，也可以读取角色卡 JSON，或自行填写背景。检查背景文本后，通过独立 API 创建游戏。

无需构建、Node 服务插件或额外依赖。离线开发预览需使用 HTTP 服务打开 `preview.html`，不支持直接双击 `file://` 运行模块。

## 当前版本能做什么

- 世界地图按需扩展：每个世界格容纳一个区域，支持负坐标与四方向持续探索；只绘制视野附近的格子。
- 区域大小：小 9×9、普通 15×15、大 21×21。由种子与世界坐标预先确定，界面只显示，不再手动选择；已有区域保持原尺寸。
- 相邻区域使用共享边界约束与对应入口，参考已生成邻区的边界和地形；模型输出必须通过边界与连通校验。
- 建筑大小上限：小 12×12、普通 24×24、大 40×40。建筑在区域生成时按用途确定大小，首次进入不会再让玩家选择；实际室内可小于上限。
- 模型描述实际宽高、房间矩形、门窗和家具坐标，插件生成网格。允许小于上限及不规则轮廓，建筑外部空白不可通行；校验出口、房间与容器可达性。
- 局部移动：选择地面并移动；选择容器或门后可自动走近，接着单独开门或搜索。关闭的门与墙体阻挡视线；已经看过的布局保留为记忆。
- 容器：独立生成战利品一次；物品先留在容器，点击拿取进入背包。离开再回来不会刷新。
- 区域调查采集、负重、补给、休息、时间与天气状态、健康/饱食/水分/体力。
- 简易庇护所及加固配方，扣除材料、消耗游戏时间，支持营地储藏与取出。正式模式会独立调用模型生成建设描述。
- 每个聊天单独存档，浏览器/宿主本地持久保存；支持 JSON 导入导出。无角色聊天时使用独立临时范围。
- 聊天发送前注入已知游戏现场。聊天完成后使用独立 API 提取线索与明确地点发现；不需要正文输出标签。
- 传闻不会直接创建战利品。未知坐标保留为待定位；冲突地点保留为待核对。可以撤销线索。
- 编辑、删除或切换消息时撤回其尚未实地探索的发现；已经探索的世界事实保留。
- 请求失败/取消不结算；切换聊天后迟到的 API 结果不会写入另一局游戏。

## 地理环境与地图表现

- 环境先由插件计算，独立模型在固定约束下补充地图。气候分寒冷、温带、干旱、热带；生态包括森林、草原、湿地、山地、海岸、荒漠、寒原和雨林。同类生态连片过渡。
- 聚落独立叠加：农村、小镇、城市郊区、城市和工业区围绕稀疏的聚落中心分布，绝大部分世界为无人荒野；“荒野独居”主题进一步降低聚落密度。废弃/破损状态仅作用于人工地点。
- 无人区生成 **零建筑**，内部不生成城市街区、农田和道路；与旧区域衔接时允许继承边界。自然地点有枯木林、野果丛、林间空地、泉眼、芦苇丛、岩洞、岩台、漂流木滩，按生态选择。
- 自然地点复用调查采集和耗尽记录。岩洞目前是可调查的洞口，尚无独立洞穴内部；天然水不会直接变为饮用水，净水和更细的采集配方后续加入。
- 前端使用 Canvas 绘制浅色纸面、地形纹理、树木岩石、农田、屋顶及营地图形；室内用木地板、砖墙、窗和家具形状表达。世界缩略图只包含已经发现的格子与地点。
- 地形信息会加入聊天的已知现场；隐藏地点和生物栖息地内部数据不会注入。
- 生物系统本次只预留每区域的 `world.ecology` 栖息地与空实体字典，随区域保存。尚无动物、敌人、巡逻、战斗、繁殖或生态模拟。

旧存档保留原来的区域与建筑；新地图绘制立即生效，生态生成只用于新区域，不重生成已探索地点。

## 三层地图与跨区域探索

地图上方使用 **世界／区域／建筑** 切换视图。切换只改变查看范围，不移动角色、不消耗时间。

1. 在世界地图选择一个相邻格子，也可用右侧的东南西北按钮定位。
2. 未生成格子的大小已确定。点击 **探索这片区域** 才调用 API；离线演示使用确定性生成器。
3. 旅行包括走到当前区域出口及跨区的 30 分钟，界面会显示预计总耗时。成功后从目标区域对应方向的入口出现。
4. 返回旧区域直接读取原存档，保留迷雾、柜子物资、营地和当地线索，不重新生成。生成失败、取消、存储失败或其他窗口已修改存档时，不结算本次旅行。
5. 目前逐个相邻区域旅行；在建筑内须先走到出口离开，再进行区域旅行。世界格子显示已发现地形的缩略图；大小、探索程度和营地数量放在右侧详情中。

旧存档自动成为世界 `(0,0)` 的小区域；原地图、建筑、战利品和营地保留。旧区域只在原有可达边缘建立出口，不重画地形；某一侧没有可达陆地时，需要从其他方向探索。

## 操作示例

演示内容随种子与坐标变化，大部分起点位于无人荒野：

1. 填写种子，点击“先体验离线演示”。可用 `testing` 体验森林无人区。
2. 地图默认放大到当前位置附近；拖动查看周边，点击“全图”查看整个区域。
3. 选择已知格子前往，抵达自然地点后调查采集；资源仅结算一次。
4. 找到建筑后探索内部，靠近门或容器，再开门、搜索与拿取。
5. 切换世界地图，选择相邻区域并探索；返回会保留原来的地图和物资。

探索不会替你发送聊天消息。点击动作按钮会直接执行插件内动作；地图选择与面板切换不消耗游戏时间。

## 聊天同步边界

- “NPC 说旧医院地下室可能有药”：新增传闻，不保证存在，不增加背包物品。
- “我发现了 (3,4) 的旧医院”：经过信息提取、证据与坐标校验后，允许补充不冲突的地点。
- “我希望附近有医院”：提取提示要求忽略愿望与假设；模型仍可能误判，记录可撤销。
- 自动定位只接受明确区域坐标、已有同名地点、或明确的“这里/此处”。仅有“北边”先保留待定位记录。
- 第一版不自动执行聊天里的交易、受伤、角色死亡和建设。它们需要后续专门规则。
- 自动提取会消耗独立 API 请求；可以关闭自动同步或现场注入。
- 插件仅向聊天提供已知地点与已搜索容器信息。全图与未搜索物资不会默认进入现场摘要。
- 主角色卡和主绑定世界书以背景文本快照保存，最长 30,000 字符；超过部分截断。初版不自动读取全局、额外绑定和关键词激活世界书，群聊请通过 JSON 或文本明确提供背景。

## 独立 API 与存档

### 多套 API 方案与模型列表

在 **游戏设置 → 独立 LLM API** 管理方案：

1. 输入方案名称，点击 **按此名称新建空白方案**；或者填写连接信息后改用新名称，点击 **另存为新方案** 复制当前表单。
2. 填写 API 地址与可选密钥，点击 **拉取模型**，从接口模型列表中选择模型；也可直接手动填写模型 ID。
3. 点击 **保存并使用当前方案**。方案分别保存地址、模型、最大输出、超时、温度与密钥保存选项。
4. 使用 **当前方案** 下拉框切换；切换会放弃未保存的表单修改。刷新后恢复上次所选方案。修改名称后保存即可重命名；可删除多余方案，至少保留一套。

旧版单套配置会自动迁移为“默认方案”。方案属于当前酒馆用户，供各聊天使用；游戏存档仍按聊天分开。每套方案的密钥默认只留在本次页面会话；需要跨刷新保存时，请单独勾选该方案的本机持久保存选项。

拉取模型发送 `GET /models`，沿用所填 API 地址的路径前缀和密钥，支持从完整 `/chat/completions` 地址推导模型列表地址。无需先选择模型，也不消耗聊天生成。接口不支持模型列表、鉴权失败或跨域受限时会提示原因，仍可手动填写。切换方案或修改地址/密钥会取消旧列表请求。

### 请求与本地存储

超时秒数没有 300 秒上限，填写 `0` 表示插件不自动超时，新方案默认不限时。已有方案保留原值，可改为 `0` 后保存。生成与拉取模型共用此设置，手动取消和切换聊天/方案的取消机制仍然有效。接口服务或代理自身的超时限制仍由服务端决定。

只支持兼容 Chat Completions 的非流式接口。背景与当前行动需要的游戏信息会发送至你填写的接口；聊天同步会发送目标消息和前两条短上下文。不会读取或复用酒馆的 API 密钥，也不会修改其连接配置。

浏览器直连要求服务支持当前宿主来源的跨域请求（CORS）。如果地址只能由服务器调用，第一版无法直接连接；不会悄悄改用酒馆主生成。

密钥默认仅保存在当前页面内存；关闭/刷新页面后重新填写。勾选“在本机持久保存密钥”会将密钥以明文存入当前宿主的本地存储。它不进入游戏存档、背景或聊天提示。未内置、不附带任何密钥。

游戏使用 IndexedDB 分区保存，按当前酒馆用户和聊天隔离。内存保留当前区域及世界摘要；普通行动只写当前区域，跨区在同一事务中保存离开和进入的区域。首次读取旧版 localStorage 存档时迁移到新存储，原始记录保留。API 方案仍保存在 localStorage。

导出 JSON 包含整个世界及全部区域；导入也支持旧版单区域 JSON。更换前端来源、清理应用数据可能导致本地存档不可用，请定期导出。没有服务器端存档同步。世界没有预设游戏边界，实际容量仍受设备内存和浏览器存储空间约束；整个世界导出时需要读取全部区域。

## 当前范围与限制

- 世界可以按需拓展，目前只支持相邻区域逐步旅行，未加入自动多区域路线和离线生成队列。
- 聊天线索按区域隔离；当前只提取当前区域的坐标与发现。世界坐标和当前区域尺寸会注入聊天；明确指向其他区域的线索暂不自动放置。返回旧区域时会重新核对其消息来源，已探索地点保留。
- 局部地图目前针对建筑，每栋单层、一个区域出入口。窗户暂时只能透视，未实现翻窗、锁具、破坏与多楼层。
- 8 类基础物资、两级庇护所；未实现复杂配方、武器战斗、NPC 实体模拟、交易或任意自由行动。
- 天气会随游戏时间变化，但复杂温度、装备保暖与疾病尚未加入。
- 区域资源只生成一次，没有生长恢复。种子稳定控制演示地图；正式模型即使使用同一种子，也不保证跨新游戏生成完全相同的世界。单局已保存世界保持稳定。
- 线索提取有逐字证据、坐标及类型检查，但语义判断仍依赖模型；误判可在日志面板撤销。
- 模型地图如果结构不合法，会自动请求一次修正；仍不合法就报错并保持原存档。

## 检查与开发

运行 `npm test` 或 `node --test tests/*.test.js`。测试覆盖游戏规则、地图连通、门/迷雾、物资守恒、持久化、撤销与异步竞态。实际 LLM 输出效果、跨域连接和宿主聊天注入仍需在目标 API/宿主中验证。

模块：`src/engine.js` 游戏状态与校验，`src/world.js` 世界边界与跨区旅行，`src/layout.js` 建筑布局，`src/region-store.js` IndexedDB 分区事务，`src/api.js` 独立请求，`src/sync.js` 当地聊天事实同步，`src/environment.js` 固定地理与栖息地，`src/map-art.js` 三层地图绘制，`src/ui.js` 面板与操作，`index.js` 宿主连接。`src/store.js` 保留旧的单区域存储实现用于兼容回归测试。

### 0.3.0 验证范围

54 项 Node 测试通过，覆盖自然区域零建筑、样本世界自然占比与连片性、固定大小、地点校验、迷雾摘要和旧存档回归。浏览器内 11 项真实 IndexedDB 检查和 6 项本地模拟 API 检查通过，人工检查 10 个地图样张及实际采集、世界切换和跨区操作。浏览器验证使用本地演示及模拟 API；未调用真实外部 LLM，未将浏览器结果视为原生酒馆宿主验证。

### 0.3.1 区域生成格式修复

兼容模型地形行中的空格、全角字符、大写字母、单字符二维数组及逗号分隔。仅统一格式，不补格、不截断、不把未知字符替换为草地；边界、生态和连通校验继续执行。错误会指出具体行、实际格数或非法字符所在列。生成请求提供目标区域尺寸模板，并明确出发区域上下文与目标区域约束的区别。

59 项 Node 测试通过，新增格式兼容、坐标保持和错误诊断检查；没有取得用户此次失败的原始模型响应，无法确认其具体字符或行长。实际外部模型仍可能返回无效内容，失败不结算旅行。

### 0.3.2 诊断与调试

打开左侧 **06 诊断与调试**，或在错误提示旁点击 **查看诊断**。

- 查看区域/建筑生成、采集、建设描述、聊天同步、拉取模型和操作错误；首次生成与自动修正分开记录，以同一组编号关联。
- 显示请求状态、时间、耗时、模型、HTTP 状态、模型结束原因、原始接口响应、模型文本和目标生成约束。
- 按全部、异常或当前聊天筛选，支持单条/全部 JSON 报告导出、导出内容预览和清空记录。诊断页面不修改游戏状态，也不自动重试请求。
- 最近最多 30 条保存在当前用户的本地存储，总量约限制为 150 万字符；单个文本字段超过 60,000 字符时标记截断。刷新后保留，页面关闭前未完成的请求标记为中断。
- 不保存请求头或 API 配置，只保留模型、接口来源域名、超时和输出长度等信息；不记录角色卡背景、聊天请求正文或全部存档。已知密钥及常见凭据字段自动隐藏。模型响应本身可能包含剧情资料，请预览后再自行分享；不会自动上传。
- 诊断写入失败会提示并保留当前页面内的记录，不阻止原游戏请求。诊断只从更新后的操作开始记录，无法找回旧版已经丢弃的模型响应。

验证：69 项 Node 测试通过；浏览器内用模拟 API 复现缺格及两次失败，确认原始返回与校验错误可见、刷新恢复，并实际下载 JSON 报告检查首次/修正记录及密钥隐藏。没有调用真实外部模型或验证原生酒馆宿主。
